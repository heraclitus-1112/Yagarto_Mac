# 内存十六进制表格设计

日期：2026-09-15

## 目标

把原生 App 内存页当前的连续十六进制字符串改为接近 YAGARTO/Insight 的经典内存表格，方便按地址观察逐字节数据，同时保留现有调试后端和读取操作。

## 界面

- 顶部继续使用现有“地址、长度、读取”控件及其校验规则。
- 读取结果按每行 16 字节显示，列为“地址”、`+0` 至 `+F` 和“ASCII”。
- 每行地址是该行第一个字节的真实地址；第一行从用户请求的地址开始，不擅自向下对齐或读取请求范围之外的数据。
- 最后一行不足 16 字节时保留空单元格，使所有行对齐。
- 字节以两位大写十六进制显示；ASCII 列只显示 `0x20...0x7E` 的可打印字符，其他字节显示 `.`。
- 表格使用等宽字体，并支持水平、垂直滚动和文本选择。
- 没有读取结果时显示简短提示，而不是空白区域。

例如从 `0x8000` 读取课程数据时显示：

```text
地址        +0 +1 +2 +3  +4 +5 +6 +7  ...  +F   ASCII
0x00008000  FC FD EE FF  01 00 00 00  ...       ................
```

表格显示内存中的原始字节顺序。ARM 小端下 `.word 0xFFEEFDFC` 显示为 `FC FD EE FF`，不为了迎合整数书写顺序而反转。

## 结构与数据流

- `YagartoCore` 的 `MIMemoryBlock` 和 GDB/MI 读取命令保持不变。
- 在 `YagartoAppSupport` 增加独立的内存表格展示模型与纯格式化器，把一个或多个 `MIMemoryBlock` 的地址和十六进制内容转换为 16 字节行。
- 格式化器验证十六进制内容；遇到单个损坏块时生成可展示的格式错误，不能崩溃或伪造缺失字节。
- `YagartoMacApp` 只负责渲染格式化后的行，不自行解析 GDB 输出。
- 本次不增加标签表达式、`$r1` 地址输入、字节编辑或自动刷新；单步后仍按现有方式由用户点击“读取”更新结果。

## 错误和边界

- 支持非 16 字节对齐的起始地址、少于一行的结果、跨多行结果和多个连续 MI 块。
- 地址溢出、奇数位十六进制、非十六进制内容或互相重叠且内容冲突的块应返回明确的展示错误。
- 没有数据与格式错误采用不同提示；原有“只能在暂停状态读取”行为不变。

## 测试

- 单元测试覆盖课程示例 `FC FD EE FF`、ASCII 替换、非对齐地址、部分末行、多个连续块及格式错误。
- App 支持层测试确认读取请求和现有校验不变。
- AppKit/SwiftUI 视图测试确认表头、16 个字节列、地址列、ASCII 列及空状态可访问标签存在。
- 运行完整 Swift 测试，确认调试、构建和工程导入功能没有回归。

## 验收标准

- 在暂停状态从 `0x8000` 读取 52 字节时，首行显示 `FC FD EE FF 01 00 00 00 ...`，首行地址为 `0x00008000`。
- 数据按每行 16 字节稳定换行，最后一行对齐，ASCII 与字节内容一致。
- 读取 `$sp` 或其他合法十六进制地址时使用同一表格，无需修改后端。
